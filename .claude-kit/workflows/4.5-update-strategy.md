## 4.5. Update Strategy Pattern (Otomatis Detect Update Tersedia + Classify Tier)

Saat kit rilis versi baru, **AI yang lakukan update analysis + execution**. Staff cuma chat natural ("ada update kit?") + confirm Y/N. Jalur CLI langsung (`npx lintasai update`) = alternatif power user / CI, bukan jalur utama staff. **Filosofi**: staff tak baca CHANGELOG 200 baris / tak klasifikasi sendiri "breaking atau bukan" — itu tugas AI: parse CHANGELOG → classify tier → ringkas Bahasa Indonesia + analogi → execute setelah confirm.

### Step 0 - Pilih JALUR update (internal git vs eksternal npm) — PENTING

Repo standar tim `ojokesusu/lintasAI` **privat** → DUA jalur, AI WAJIB pilih yang PASTI jalan:
- **Internal** (akun **diundang** ke repo) → `npx lintasai update` (`git clone` + cadangan otomatis + banner `[SECURITY]`).
- **Eksternal** (tak diundang) → `npm create lintasai@latest` (pasang-ulang dari npm publik). `npx lintasai update` **ditolak** (menarik dari repo privat).
- **Cara pilih:** owner/staff sudah bilang jenisnya → pakai itu; ragu → **default `npm create lintasai@latest`** (pasti jalan, tak butuh akun GitHub); `npx lintasai update` gagal "gagal ambil daftar versi" → **otomatis beralih** ke `npm create lintasai@latest`. Detail: `UPDATE_KIT_PROMPT_v1.md` Step 0.

### Kapan AI auto-trigger update analysis

1. **User chat eksplisit**: "ada versi baru? / update kit / kit perlu update? / version check / vX.Y rilis / cek update".
2. **Versi spesifik**: "v1.2.0 rilis", "update ke v1.5.0", paste link release notes.
3. **Awal sesi (OPSIONAL, low-noise)**: `.claude-kit/` terdeteksi + user belum brief task → boleh silent-check upstream (`CHANGELOG.md` HEAD vs baseline); gap >0 → sebut singkat di akhir greeting, JANGAN block task lain.

**JANGAN auto-execute update tanpa confirm** — update = re-clone destruktif (walau ada backup); popup confirm dulu (§14).

### 4-Tier Classification Algorithm (WAJIB urutan dari atas)

AI baca tiap CHANGELOG entry yang BELUM ada di versi kit user, lalu classify pakai rule ini **urutan dari atas ke bawah** (tier paling restrictive menang kalau ambigu):

| Tier | Pemicu di CHANGELOG entry | Staff action |
|---|---|---|
| **4 [SCAN-REQUIRED]** | Prefix `[SCAN-REQUIRED]` di awal entry | Re-paste `PROJECT_LIFECYCLE_PROMPT_v1.md` Stage 1/2 (re-bootstrap full) |
| **3 [BREAKING]** | Prefix `[BREAKING]` di awal entry | Baca "Migration Steps" inline di CHANGELOG + execute step-by-step |
| **2 (AI auto-sync)** | Tanpa label, tapi entry mengandung kata: "tambah section", "fitur baru", "aturan AI", "rule baru", "section X.Y baru", "expand pattern" | 1 perintah (`npx lintasai update`, atau minta AI "update kit"), AI auto-pakai aturan baru di sesi berikut |
| **1 (Silent)** | Tanpa label, tapi entry mengandung kata: "fix typo", "perbaikan ringan", "minor fix", "clarify wording", "rephrase" | 1 perintah, no behavior change |

**Edge cases**:
- Entry punya `[BREAKING]` + `[SCAN-REQUIRED]` → pakai Tier 4 (paling restrictive).
- Entry tanpa label tapi ambigu (mis. "refactor section 4.3 jadi 2 file") → AI ESKALASI ke Tier 3 [BREAKING] secara defensif. Lebih baik over-cautious daripada miss-detect breaking.
- Multi-version jump (v1.0 → v1.5, lewat 5 entry) → AI classify TIAP entry, ambil tier TERTINGGI sebagai tier eksekusi. Tapi summary jelaskan per-version (lihat format di bawah).

### Format Summary WAJIB (dengan analogi tools digital)

Setelah AI classify, output summary ke user dalam format ini (BUKAN dump CHANGELOG mentah):

```markdown
## Update lintasAI tersedia: v<X> → v<Y>

**Ringkasan plain Indonesia**: <1-2 kalimat, no jargon>

**Tier <N>**: <analogi tools digital satu kalimat - WAJIB pakai library tools populer>

**File akan berubah** (overwrite dari upstream):
- `./.claude-kit/<file1>`
- `./.claude-kit/<file2>`

**File preserved** (user-modified, di-backup ke `*.bak.<timestamp>`):
- `./.claude-kit/<file3>` (manifest sha256 mismatch dengan upstream baseline)

**Action staff**:
- Tier 1/2: TIDAK ADA - habis confirm, selesai. AI auto-pakai aturan baru.
- Tier 3: Baca "Migration Steps" CHANGELOG entry + execute step-by-step (AI bantu propose tiap step).
- Tier 4: Re-paste `PROJECT_LIFECYCLE_PROMPT_v1.md` Stage 1/2 (AI panduin bulk-bootstrap ulang).

**Confirm**: ketik `ya` untuk execute, atau `nanti` untuk skip (rekomendasi kalau ragu — paling aman, tidak ada file yang ditimpa dulu; update bisa kapan saja).
```

### Library analogi tools digital untuk tier (WAJIB pakai salah satu)

- **Tier 1 (Silent)**: WhatsApp/Chrome auto-update di background (cuma notice sebentar).
- **Tier 2 (AI auto-sync)**: iOS minor update (restart sekali, fitur baru aktif, app lama jalan); Notion rilis fitur baru otomatis muncul.
- **Tier 3 [BREAKING]**: iOS major upgrade (backup wajib, migration screen minta confirm, beberapa app re-login); WhatsApp chat migration Android→iPhone.
- **Tier 4 [SCAN-REQUIRED]**: Tokopedia/Shopee Seller ganti sistem kategori/variant — semua listing lama wajib re-map manual.

Perubahan di luar pattern → AI bikin analogi konsisten **dari tools populer Indonesia-context** (§4.4). **Dilarang** analogi jargon programming ("merge commit", "rebase", "diff tree").

### Dual-Mode Execution Flow

**Mode A: AI Chat Mode (DEFAULT staff non-programmer)** — urutan: (1) trigger detected; (2) AI fetch CHANGELOG.md upstream; (3) parse versi user dari `.claude-kit/CHANGELOG.md` / AGENTS.md "Versi kit aktif"; (4) diff entry baru; (5) classify tier (ambil tertinggi); (6) compose summary (format wajib); (7) tampilkan + popup confirm §14 (ya/nanti/batal); (8) "ya" → execute per **Step 0** (internal→`npx lintasai update`; eksternal/ragu→`npm create lintasai@latest`); (9) parse output → lapor hasil; (10) update AGENTS.md "Versi kit aktif" + "Riwayat update kit"; (11) Tier 3 → propose Migration Steps (per-step confirm); (12) Tier 4 → prompt re-paste `PROJECT_LIFECYCLE_PROMPT_v1.md` Stage 1/2.

**Mode B: CLI langsung (power user / CI)** — `npx lintasai update` direct: auto-classify tier + structured output (tabel tier/entry + file changed/preserved + exit code). Kalau user paste output ke chat minta interpret → AI klasifikasi ulang + summary format wajib.

### Backup Retention Rules (AI WAJIB lapor saat cleanup)

`update-kit.mjs` auto-jaga retention: (1) hapus `*.bak.<timestamp>` >30 hari; (2) keep max 3 backup terakhir per file (ke-4 dst auto-deleted); (3) TIDAK ADA folder `migrations/` per breaking — Migration Steps **inline di CHANGELOG entry**. Saat cleanup, AI WAJIB sebut di laporan post-update file mana yang dihapus/di-rotate + disk reclaimed (transparansi — staff tahu file lama dihapus, bukan silent cleanup yang bikin panik).

### Migration Steps untuk Tier 3 [BREAKING] (AI workflow)

Tiap entry `[BREAKING]` WAJIB punya `### Migration Steps` inline dengan perintah eksplisit. Saat Tier 3:
1. Setelah `npx lintasai update` selesai → baca "Migration Steps" entry relevan.
2. **Propose step-by-step, JANGAN bulk-execute.** Tiap step: command + analogi singkat + confirm Y/N.
3. **Per-step confirm** (§14): `ya` lanjut / `lewati` skip / `batal` stop (lapor state: step N/M selesai).
4. Setelah semua selesai → verify pakai command "Verification" CHANGELOG (kalau ada) / scan basic (file+anchor exist).
5. Update AGENTS.md "Riwayat update kit" ("Tier 3 BREAKING - migration steps N/N selesai").

User batalin di tengah → AI WAJIB lapor di sesi berikut ("update v<X>→v<Y> di-pause di step 3/7, lanjut?") — JANGAN silent-forget.

### Dua Keranjang Migrasi — LANGSUNG (eager) vs boleh MENYUSUL (lazy)

Istilah: **eager** = diterapkan LANGSUNG saat update; **lazy** = ditunda sampai area disentuh. Salah taruh = bom waktu "version skew senyap" (sebagian format lama, sebagian baru).

**Keranjang 1 — WAJIB LANGSUNG (eager), dikunci label `[BREAKING]`:**
1. 🔒 **Keamanan / tier / kunci** — `.staff-profile.md`, wiring hook risk-gate/secret-guard.
2. 🗄️ **Format data / penyimpanan** — `project.lintas.jsonc`, `.install-manifest.json`, buku-besar migrasi, portfolio yml, consistency-map, BUKU_PELAJARAN.
3. 🗂️ **Registry / indeks** — staff-roster — dimigrasi **SATU SET utuh** (separuh = link menggantung → AI salah baca).

Aturan main Keranjang 1 (saat memandu update Tier 3):
- Tiap **kenaikan `schema_version`** artefak klien = WAJIB entri CHANGELOG `[BREAKING]` + `### Migration Steps`. **Dikunci MESIN**: robot preflight (`checkSchemaRaiseBreaking`, `tests/preflight.mjs`) gagalkan gerbang (GENTING) kalau angka `lib/expected-schema.mjs` naik tanpa label itu.
- Migrasi dijalankan **LANGSUNG** (per-step confirm): **SIMULASI dulu** (jalan pura-pura → tinjau → terapkan; §2.1 #7 sebut "SIMULASI", bukan "dry-run") + idempoten + salinan cadangan ber-cap-waktu, lalu **DICATAT** ke `.migration-state.json` via `recordLintasMigrationApplied` (`lib/migration-state.mjs`) supaya tak dobel.
- Tiap rilis `[BREAKING]` WAJIB punya bagian di **`UPGRADING.md`** (kerangka entrinya ada di berkas itu). Preflight menagih: kenaikan skema tanpa SIMULASI / tanpa entri UPGRADING.md = peringatan PENTING.
- **Penagih otomatis:** robot laporan-migrasi (doctor 2c + update Langkah 7) tetap MERAH ("Selesai sebagian") sampai semua artefak menyusul.

**Keranjang 2 — BOLEH MENYUSUL (lazy): HANYA dokumen saran / pola opsional** — docs pendamping `.md`, template contoh, gaya/format:
- AI menyentuh dokumen yang format-nya berubah di kit baru → **TAWARKAN** migrasi dokumen ITU saja via popup (§6.2/§6.4): *"[1] Rapikan ke format kit baru (rekomendasi) — cuma berkas ini, aman & gampang dibalik / [2] Biarkan dulu"*. **DILARANG auto-bulk** tanpa persetujuan per-berkas.
- Lazy AMAN karena fallback: dokumen format lama **tetap terbaca** (sifatnya saran) — beda dari Keranjang 1 yang dibaca mesin/robot (salah format = salah vonis).

**Pembeda keranjang (kalau ragu):** tak bisa sebut *"prompt persis apa yang memicu migrasi ini"* → tak punya "area sentuh" andal → **Keranjang 1 (eager)**. Perubahan lintas-potong (aturan keamanan, robot lintas-berkas) SELALU eager.

🏢 Analogi: **recall mobil** — rem & rangka (keamanan + format data) WAJIB dibereskan SEKARANG dengan surat resmi (`[BREAKING]`); stiker panduan dashboard boleh diganti pas servis berikutnya (lazy) karena stiker lama pun masih terbaca.
